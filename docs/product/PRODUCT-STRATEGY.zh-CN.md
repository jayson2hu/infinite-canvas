# Infinite Canvas 二次开发产品方案

> 本文是面向国内个人创作者与小团队的建议方案，不代表功能已经实现。首版采用邮箱注册，预留手机号和微信登录。金额、赠送额度、并发、保存期限与时限均需结合实际供应商、预算和运营规则确定，本文不把示例设为生产默认值。

## 1. 产品判断与改造边界

建议将产品定位为「能保存创作过程、反复修改并交付作品的 AI 视觉工作台」。首版优先服务内容封面、营销配图、商品视觉方案等连续改图场景，避免同时承担完整设计软件、视频平台与自动化 Agent 平台的交付范围。

首批模板围绕三种可交付任务设计：内容创作者从标题和风格参考生成封面并比较变体；小商家用商品参考图迭代场景图并导出不同渠道比例；小团队成员从活动文案与品牌素材生成宣传配图并保存修改过程。商品图需强调保留关键商品特征，用户在发布前核对实际一致性；模板不承诺生成结果自动符合广告或平台要求。

已有基础可以复用：无限画布、节点编排、文生图与参考图编辑、提示词和素材管理。商业化新增的关键价值是：用户无需自行购买和配置 API，作品跨设备保存，任务状态可信，花费可预期，问题可追溯。

已核实的仓库基线：

- `README.md` 明确说明浏览器直连用户配置的 AI 接口，API Key、Base URL、画布、素材和生成记录默认存在浏览器本地。
- `web/src/stores/use-user-store.ts` 只有本地用户形状和清空状态，没有据此证明已具备账户体系。
- 上游提供远程节点插件、自定义调用脚本与本地 Agent 能力。面向公众收费后，这些能力需要重新确定信任边界。
- 仓库说明项目处于开发阶段；现有 Docker 入口不能等同于已通过商业多用户生产验收。

因此，增加注册和积分不是两个前端页面，而是账户、任务、计费、存储和运营的完整改造。公开收费模式下，供应商密钥必须在服务端，积分授权必须在服务端执行。

## 2. 首版用户闭环

1. 用户可先浏览产品说明、模板示例和计费规则；申请使用时完成邮箱验证。
2. 从空白画布或一个明确用途的模板开始，添加文案与参考图。
3. 选择由平台审核启用的模型与参数，生成按钮展示本次积分报价；批量任务同时展示数量和总额。
4. 点击生成后保留任务卡片，展示排队、生成中、结果处理中或待核实状态；刷新和换设备仍能查询。
5. 成功结果进入原画布，并记录输入、参数和关联素材，用户可以继续修改、比较版本和导出。
6. 余额不足时保留当前编辑内容，充值返回后恢复操作，由用户再次确认提交，避免自动启动旧任务。
7. 用户可查看积分明细、充值订单、任务费用和失败原因，并通过任务编号反馈问题。

首屏重点展示「继续上次项目」和少量经过验证的模板。模型的用途、效果与费用应优先于供应商技术参数。基础编辑、查看和导出不额外消耗生成积分；会调用付费模型的助手操作也必须报价或展示用户事先确认的费用上限。

## 3. 首版范围与后续版本

| 阶段 | 交付内容 | 完成标准 |
| --- | --- | --- |
| 内部验证 | 邮箱账户、个人项目、服务端生图、任务队列、积分账本、管理员有审计的额度发放 | 真实供应商任务能够从提交到结果落盘完成；失败、重试与重启不产生重复扣费 |
| 受控试用 | 邮箱验证后的限量体验、反馈入口、告警和对账、明确的保存与退款规则 | 真实用户可以独立完成首张作品；成本、交付率和邮箱送达情况可观测 |
| 对外收费 | 合规商户渠道充值、订单核验、支付与积分对账、退款处理、服务条款与隐私说明 | 支付异常、订单重复回调和退款等关键验收通过，线上支持与恢复流程可执行 |
| 后续增强 | 手机号/微信身份绑定、团队空间与角色、共享钱包、项目分享、订阅权益 | 依据付费留存与协作需求逐项验证，不与首版同时展开 |

首版将小团队视为使用相同产品的多名个人。不得暗示已具备团队资产归属、共享积分或实时协同；这些能力需要单独建模和验收。公开插件市场、任意自定义接口、任意脚本和本地 Agent 不纳入首版托管服务的普通用户流程，已有本地能力可以保留为独立开发用途。

首版聚焦图片生成与参考图编辑，视频、音频、团队共享钱包后置。项目云端保存属于收费版最低闭环，不能用「账户已登录」代替作品已经同步。

## 4. 注册、身份与防滥用

### 邮箱优先

- 首版推荐邮箱一次性验证码（OTP），注册与登录复用同一入口，使用成熟身份组件实现；不额外加入密码及找回密码流程。
- 验证码或验证链接应一次性使用、按用途绑定，具备有效期和尝试限制。邮件发送结果不能被当作验证成功。
- 邮箱发送、验证、登录、找回、注册赠送分别设置风控和成本预算；具体阈值需在上线配置中确定，防止邮件通道被刷。
- 前端对账户是否存在使用一致回复；账户锁定、邮件退信和验证码失效应给用户可执行的恢复路径。
- 会话应支持退出及服务端撤销，不能以浏览器 store 或可篡改的用户 ID 判定身份。

推荐流程：用户输入邮箱并获知账户/隐私条款 → 服务端以统一响应发送验证码 → 用户提交邮箱、挑战标识和验证码 → 服务端验证用途、时效、尝试次数并原子消费挑战 → 为首次用户创建账户、为已有用户读取账户 → 建立可撤销会话 → 前端获取当前账户与钱包。首次注册条款版本与同意记录和登录验证分开存储，营销订阅单独选择。

服务端仅存验证码的安全验证材料，不在日志中输出明文验证码。验证码挑战绑定邮箱及用途；并发验证也只能成功消费一次。登录成功后轮换会话标识，通过设置 `HttpOnly`、`Secure` 与合适 `SameSite` 的 Cookie 传递，并为有副作用的接口提供 CSRF 防护。退出时服务端吊销会话；账户敏感操作要求重新验证。验证码位数、时效、重发间隔及会话期限按所用身份组件和风险评估确定，上线前形成可审阅配置。

### 为手机号和微信留接口

账户主键使用内部稳定 ID，邮箱、手机号和微信作为关联身份。不要将邮箱字符串直接用于钱包、订单或素材的归属键。以后绑定新身份时，需要同时验证当前账户和新身份，禁止仅按同名邮箱或昵称自动合并资产。

微信网页登录、公众号网页授权与小程序登录属于不同接入场景，实际入口取决于已申请的平台资质与应用。设计上保留提供方、应用作用域和身份标识字段；不要预设所有场景都能获取统一标识。

### 体验积分

- 邮箱验证只是发放条件之一，不能证明「一个人只有一个账户」。建议先采用受控试用或限量体验，观察真实成本后放开。
- 每次发放绑定唯一活动与账户组合，服务端幂等；独立记录赠送批次、来源、有效期与可用模型范围。
- 结合账户行为、请求速率、IP 聚集等信号识别批量注册；IP 不能作为唯一封禁依据，避免误伤公司或学校网络。
- 设置活动总预算、单账户消耗范围、风险账户暂停与人工复核。不要把高额注册赠送、无限签到或多级邀请奖励作为首版增长方式。
- 风控采集应与隐私说明一致，并尽量少收集数据；普通用户无需为体验被强制索取与用途无关的信息。

## 5. 积分规则：先报价，再预占，最后结算

### 账本与余额

积分使用整数最小单位，人民币订单使用整数分；都不使用浮点数。区分付费积分与赠送积分，保留来源批次、有效期、冻结和消耗分配。页面展示「可用积分」「任务占用」「积分明细」，避免余额变化无法解释。

账本采用不可变记录：充值入账、赠送、预占、结算、释放、消费退还、到期、现金退款引起的积分回收、运营调整。发现错误时增加冲正记录，不覆盖历史。钱包余额可以作为事务维护的汇总，但必须能从账本重建并与账本校验。

核心约束：可用积分与占用积分均不为负；一次业务事件只能生效一次；一次任务只能完成一次最终结算。并发检查与预占在同一数据库事务内完成，不能先读余额再单独扣减。

### 报价与提交

服务端根据受控模型、操作类型、分辨率、质量、数量以及计价版本生成报价，保留价格快照。前端提交报价 ID 与幂等键，服务端复核有效期、账户、输入参数及余额。参数变化或报价失效时必须重新展示价格，禁止静默提价。

定价明确的图像任务优先采用固定价格。对按输出量结算的文本或其他任务，事先展示可理解的最高消耗并预占上限；实际收费不能超过已确认上限，需要更高预算时重新获得用户确认。

生成请求必须统一经过同一服务端计费入口，包括画布、图片工作台、助手、批量操作、重试及未来插件入口。隐藏一个前端按钮无法防止绕过积分。

### 状态与结算

| 情形 | 积分处理 | 用户体验 |
| --- | --- | --- |
| 未通过参数、权限、内容前置检查 | 不创建付费上游任务，不占用或立即释放 | 明确说明修改项 |
| 已接收并排队 | 原子预占，创建可恢复任务 | 显示占用和排队状态 |
| 成功且结果已持久保存、可交付 | 按价格快照结算，释放未用部分 | 展示本次消耗并关联结果 |
| 一批任务部分成功 | 按可独立交付的子任务结算 | 展示成功数量与退还/释放明细 |
| 明确失败且未交付结果 | 释放占用；如先前已结算则通过补偿记录退还 | 说明任务失败，允许重新报价重试 |
| 尚未提交供应商时取消 | 释放占用 | 显示已取消 |
| 已提交供应商后取消 | 仅当上游确实支持取消时显示可取消；费用规则事先明确 | 不把浏览器停止等待视为任务取消 |
| 网络超时、回调未到、上游结果不明 | 进入待核实，查询供应商任务并对账 | 展示处理状态，避免立即重扣或无期限无解释占用 |

普通生成失败可由平台承担已经发生的供应商成本，以保证对用户的承诺；这部分必须计入定价。失败退款、内容拒绝和取消规则要在购买与提交前可见，不能事后根据供应商是否收费临时决定。

重复提交、重复回调、乱序事件、工作进程重启与队列重新投递，都必须命中相同任务/结算幂等约束。数据库中的任务和预占提交成功后，通过可靠出站事件或可恢复扫描进入队列，避免「扣了积分但任务没入队」。

对供应商不支持幂等提交且接收结果不明的请求，不自动发起第二次付费请求；保存请求关联信息，先查询或人工核实。可用性切换和供应商故障转移也必须遵循这个约束。

积分按公开规则从批次分配，例如优先使用即将到期的赠送积分。预占期间如何处理到期应固定并公开；释放回原来源时必须保留原属性，不能把赠送积分转换成现金可退款资产。

## 6. 充值、定价与运营

### 商业模式

首版建议「基础编辑免费 + 按生成用量消耗积分 + 单次购买积分包」。先验证付费与复购，再增加订阅所包含的积分、存储和服务权益。不同模型和参数不同价，不承诺无限生成。

购买页至少说明：支付金额、到账付费积分、赠送积分、适用范围、有效期、退款规则、典型任务大致可生成数量。典型数量必须注明对应模型与参数，随价格版本更新；不借低成本模型数量暗示所有模型都适用。

交互原型使用纯演示数值：初始余额 120 积分，普通图片操作 12 积分，高质量操作 24 积分。假设无赠送到期及其他消耗，对应最多 10 次或 5 次操作；提交 12 积分任务后显示可用 108、占用 12，成功后累计消耗 12，失败释放后恢复可用 120。该示例不代表注册赠送额度、真实模型价格或任何人民币兑换比例。

不从仓库 README 的赞助文案推断采购价、可用性或转售权。应取得供应商实际计费、并发、保留期限、数据处理、服务区域和商业使用条款，再计算价格。

设单次服务的非支付变动成本为 `C`，包含模型、失败与重试分摊、存储、下载流量及其他按量成本；支付费率为 `f`，目标贡献毛利率为 `m`，则可用 `价格 >= C / (1 - f - m)` 做初步下限估算，要求分母为正。固定运维、人力和获客费用另算整体盈亏；模型差异和赠送补贴分别核算。本文不给未经核实的人民币套餐和供应商成本。

### 支付入账

- 由服务端创建订单，保存支付金额、币种、积分包版本及购买主体；前端支付成功页面不作为入账依据。
- 使用支付渠道要求的签名验证，并核验商户、订单、金额、币种与终态；通过唯一支付流水和订单状态保证仅入账一次。
- 支付回调与主动查单互补。重复、延迟、乱序回调不能重复发积分，也不能把已退款订单恢复成已支付。
- 现金退款与任务积分退还为两种业务。现金退款需核算原订单尚可回收的付费积分、已用权益及赠送规则，并在支付侧确认后落账；冻结占用中的积分先处理关联任务，不能造成负余额。
- 人工赠送、补偿、退款和封禁要求理由、操作者及审计记录；管理员不能直接在数据库中改余额作为常规操作。
- 对账覆盖支付订单、支付渠道流水、积分入账、任务结算、供应商消耗和退款；异常进入可处理的运营列表。

没有正式商户和支付通道之前，可在受控测试环境使用明确标注的测试订单或管理员体验额度验证闭环。不得把测试支付页或模拟回调当作可对外收款的功能。

### 最小运营后台

需要账户与风控状态、任务与供应商请求状态、积分账本、订单退款、模型与价格版本、活动额度和总预算、告警与审计。涉及金额和权限的操作采用角色隔离，管理员账户启用更强认证。

任务详情能够回答四个问题：用户提交了什么操作、系统预占了多少、供应商执行到哪一步、最终交付和扣费是否一致。默认日志不收集完整私密提示词或素材内容。

## 7. 项目与素材体验

注册账户后的用户通常预期作品不会随着浏览器清理而消失。建议把项目云端保存和生成结果持久化纳入收费版最低要求，同时保留本地导出。

- 云端项目、素材、任务、账本与订单全部绑定服务端验证的所有者；下载地址也不能绕过归属检查。
- 画布采用版本号和自动保存状态，网络中断保留本地编辑缓存；冲突时提示另存副本或选择版本，不静默覆盖。
- 本地旧项目进入云端前由用户选择导入并显示数量和状态，原本地数据先保留；退出账户后不得把上一账户缓存显示给下一账户。
- 对象存储为私有访问，采用短期授权地址；复制链接不代表永久公开分享。用户主动分享时单独设置范围与撤销方式。
- 供应商临时结果地址不能作为最终资产。结果持久保存成功后，才按可交付结果处理结算。
- 明确保存期限、存储配额、超额行为、导出和删除方式；删除账户时区分可删除创作数据与依法/依合同需保留的交易记录，公开实际保留规则。

首版可以只实现单用户多设备编辑和冲突检测，无需引入实时协同框架。团队版本后续再明确管理员、成员、访客、退出后作品归属和共享钱包预算。

## 8. 自部署与国内交付约束

建议按职责部署 Web 前端、业务 API、异步任务进程、关系数据库、任务队列及对象存储，入口统一 HTTPS。业务 API 管理账户与计费，任务进程调用供应商；对外接口不能允许普通用户指定任意上游 URL 或取得平台密钥。

部署区域需要通过真实请求验证模型连通性、邮件送达、上传下载和回调到达情况。若使用境外供应商，应查清服务区域、个人信息和素材如何流转、合同及数据处理安排；不能把网络代理视为采购或合规结论。

面向中国大陆公开运营时，应根据实际服务器地区、经营主体、功能和内容类型核对域名及网站相关手续、支付商户资格、隐私告知、用户协议、内容审核和生成内容标识等适用要求。涉及具体备案或监管分类的结论，应由相应主管渠道或专业顾问确认；本方案不将某一种架构直接判定为合规或不合规。

上线必须具备：

- 秘密管理与密钥轮换，浏览器、日志和项目导出均不携带平台供应商密钥。
- 数据库备份与恢复演练、对象存储生命周期、任务恢复、价格配置回滚和版本发布流程。
- 邮件域名的 SPF/DKIM/DMARC 配置、主流国内邮箱实际送达与退信处理。
- 用户级和供应商级并发控制、总消耗预算与紧急停用开关。具体边界值需按采购配额与试运行结果确定，并明确超限后的排队或拒绝方式。
- 公共插件/脚本与本地 Agent 的隔离。未经评估的脚本不能获得账户会话、私有素材、充值权限或在服务器上执行；本地 Agent 端口不得直接成为多用户公网接口。
- 上游下载与上传的文件类型、体积、地址解析和目标网络检查，避免恶意媒体和任意内网访问；具体限制应公布给使用者。
- 用户支持入口、事件处理负责人及对账异常的处置方式。不要在没有测量和演练之前承诺具体可用性百分比。

## 9. 验收：收费前必须通过

| 验收场景 | 通过条件 |
| --- | --- |
| 邮箱注册与验证 | 未验证账户不能领取对应权益；重复验证和重复活动请求不重复发放；邮件发送失败可以恢复 |
| 账户隔离 | 账户 A 不能读取、修改或下载账户 B 的项目、素材、任务、订单与账本；更换 URL 中的 ID 仍被拒绝 |
| 并发余额 | 在余额只够一次任务时并发提交多个任务，只有允许的任务成功预占；无负余额 |
| 报价与参数篡改 | 修改模型、数量、分辨率、账户或价格后不能沿用原报价；有效报价按原价格快照执行 |
| 请求重复 | 重复点击、网络重发、队列重投不重复创建收费任务或重复扣费 |
| 供应商重复/乱序回调 | 最终任务状态、结果与账本一致；后到的旧事件不能覆盖终态 |
| 异步中断恢复 | API 或任务进程在预占后、提交上游后、保存结果前后重启，仍可恢复并最终对账 |
| 结果不明 | 超时进入可追踪核实流程，不自动重复付费请求，不提前制造可重复消费的退款余额 |
| 失败及部分成功 | 无可交付结果的任务按公开规则释放/退还；成功子任务只结算一次；用户可核对明细 |
| 支付回调 | 假签名、错商户、错订单、错金额均不入账；正常回调和主动查单只入账一次 |
| 退款与批次 | 付费和赠送来源保持可追溯，未用积分回收与现金退款一致，已占用积分不能被重复回收 |
| 数据与存储 | 清理浏览器后可恢复已保存项目；供应商临时地址失效不影响已交付作品；删除规则可验证 |
| 成本保护 | 关闭模型或触达总预算后不再发起新付费任务，已有任务按既定规则结算 |
| 运维恢复 | 可以在隔离环境从备份恢复账户、项目、订单和账本，并完成一致性对账 |

## 10. 衡量与实施决策

北极星指标建议使用「每周完成并导出作品的活跃创作者」，结合继续编辑和再次使用衡量实际价值。首次成功生成率、从注册到首个作品的时长、项目继续编辑率、付费转化、复购和留存反映产品体验；任务交付率、平均真实成本、赠送补贴、退款率和每个付费用户贡献毛利反映经营质量。

发布顺序按依赖推进：确定身份与数据归属 → 打通一种图像能力的服务端任务 → 完成积分账本与异常恢复 → 云端保存和基本后台 → 小范围试用与成本测量 → 确认价格和支付商户 → 完成真实支付/退款验收 → 对外收费。不要在任务和积分闭环尚未验证时接入大量模型。

开始实现前仍需明确的经营输入：运营主体与部署区域、供应商与采购条款、可承担的体验总预算、正式积分价格与有效期、云端保存政策，以及支付渠道。除这些会影响实际费用、权限或用户承诺的事项外，身份结构预留、接口划分和文档准备可以先推进。
