# 创作者工作台：产品与用户体验重设计

## 1. 设计结论与适用范围

将产品组织为「从一项创作任务开始，在项目中持续修改，最后导出可用作品」。无限画布是承载参考、方案和版本的工作空间；用户无需先理解节点、连线、渠道和模型，就应知道第一步做什么。

已确认的用户范围是国内个人创作者与小团队；账号方案是先邮箱注册，预留手机号与微信。进一步聚焦「商品视觉」和「内容封面」属于本次设计假设，仍需真实访谈和使用数据验证。小团队不等于首版必须实时协作：先把个人交付、版本传递与文件导出做好，再验证共享项目需求。

本文件同时记录本轮前端改造范围与后续设计依据，不代表已经上线。当前源码仍以浏览器本地数据和用户自带 AI 接口配置为基础。真实账号、平台积分、服务端任务、云端项目保存属于后续 SaaS 阶段；此前独立的积分原型不应作为生产能力呈现。实际验收结果与尚待人工确认的内容分别保存在 `ux-review/` 和 Pending Tests 中。

### 本轮已实现范围与视觉决策

本轮直接修改 `web` 应用：首页已改为任务工作台，填写项目名与需求后创建真实文本简报，并连接到状态为 `idle` 的待生成图片节点；此操作不调用 AI，也不发起扣费。首页按最后编辑时间展示最近项目。项目列表加入搜索、排序、作品预览与选择后的批量操作，将「删除全部」收到更多菜单，并分别处理读取中、没有项目与搜索无结果。

顶部主导航已调整为「工作台 / 我的项目 / 素材库 / 灵感库」，图片、视频、设置和本地 Agent 收入「创作工具」。主题保持直接可切换，语言、帮助、版本和上游项目归入偏好菜单；桌面与移动端采用相同的信息层级。改造提供中英文案和浅深色布局，浏览器验收、脚本与真实应用截图集中在 [ux-review](./ux-review/)，最终通过范围需以该目录的报告为准；不将旧独立原型的测试当作此次应用验证。

设计采用安静的创作工作台风格：左对齐内容、清晰输入区、有限的主行动和真实项目预览，避免大面积宣传标题压过任务。沿用现有 [画布主题](../../web/src/lib/canvas-theme.ts) 的 `canvas.background`、`node.panel`、`node.text`、`node.muted`、`node.stroke`，以及 [应用主题](../../web/src/lib/app-theme.ts) 的 Ant Design 全局颜色和交互 token。浅色基底为现有暖灰 `#f4f2ed`、面板 `#fbfaf7`；深色对应 `#181715`、`#1f1d1a`。这些色值是对已有 token 的说明，组件应从 token 读取，不建立第二套硬编码主题。

按钮、下拉菜单、焦点和悬停复用现有组件与全局规则；普通动作保持低视觉重量，选中态才使用选中底色。项目预览优先真实素材，空项目使用结构化占位，绝不以虚构成品暗示生成已完成。此次不继续扩展独立 sidebar 静态原型来替代应用功能。

## 2. 现状审查：证据与判断分开

下列源码观察以本次重设计前的页面为基线，文件链接用于追溯问题来源。

| 源码中可确认的事实 | 对体验的判断 | 设计动作 |
| --- | --- | --- |
| [原首页](../../web/src/pages/home/index.tsx)的大标题区域最小高度为 620px；「开始使用」取导航首项，和「打开画布」都进入 `/canvas` | 用户难以区分两个行动；工作入口与过往项目不在首页形成闭环 | 把首屏改为任务起步与继续创作，保留一个清晰的主行动 |
| 首页请求外部提示词列表，用大图预览作为展示行为 | 用户看到效果，但点击后仍不一定开始创作；展示源失败还会打断首页 | 灵感内容后置到独立入口；工作入口不依赖灵感源加载成功 |
| [导航定义](../../web/src/constant/navigation-tools.ts)将画布、生图、视频、提示词、资产、配置列为同级 | 按内部工具分类，需要新用户自行拼成流程 | 一级导航围绕创作、项目、素材；视频和配置保持可发现的次级入口 |
| [项目列表](../../web/src/pages/canvas/index.tsx)空态说明「节点、连线和画布外观」，页头直接展示「删除全部」 | 空态解释数据结构，没有给出一个作品目标；危险操作过于突出 | 用作品任务解释新建入口，批量管理进入显式管理状态 |
| [项目卡](../../web/src/components/canvas/canvas-project-card.tsx)主要展示标题、节点和连线数量 | 节点数不等于项目价值，用户不易认出上次做到哪一步 | 优先展示作品标题、预览、最近编辑和继续按钮；复杂度信息后置 |
| [项目 Store](../../web/src/stores/canvas/use-canvas-store.ts)更新 `updatedAt` 时不重排项目数组 | 数组第一个项目不一定是最近编辑的项目 | 「继续最近」按更新时间排序，排序不修改原 Store 数组 |
| 同一 Store 使用 localforage 延迟持久化，没有可供 UI 使用的写入完成与失败状态 | 静态「本地保存」可以说明保存位置，但不能据此显示每次操作均已保存成功 | 当前说明保存范围并提供导出；真实保存状态需在写入完成后更新 |
| [配置 Store](../../web/src/stores/use-config-store.ts)默认 API Key 为空，并有按选中模型关联渠道的就绪判断 | 创建项目和 AI 生成的可用条件不同 | 编辑允许先行，提交 AI 请求前精确检查所选能力，不能只看是否存在任意 Key |
| [画布页面](../../web/src/pages/canvas/project.tsx)已有生成、编辑、结果分支、引用与导出能力 | 核心能力可复用，价值在于降低入口理解成本 | 首页创建真实项目和可编辑内容，不另建脱离画布的演示工作流 |
| [统计模块](../../web/src/lib/analytics.ts)默认关闭，现有逻辑以页面浏览统计为主 | 暂无证据证明某类用户留存、模板效果或转化提升 | 先定义事件与口径，隐私告知完成后再接入产品统计 |

这些观察说明存在可改进的路径，不构成用户已经遇到各类问题的量化结论。当前没有可引用的转化率、满意度或任务耗时基线。

## 3. 产品边界：先完成一件有用的事

本轮入口提供以下四类创作起点；场景优先级仍需目标用户验证：

| 入口 | 用户提供 | 在画布中得到的起点 | 成功的定义 |
| --- | --- | --- | --- |
| 商品视觉 | 商品、用途、希望保留的细节；可添加商品参考图 | 可编辑的创作说明与参考组织方式 | 用户选择一张符合要求的图并导出 |
| 内容封面 | 主题、发布场景、主体与视觉方向 | 可编辑的封面说明；具体输出比例由用户确认 | 导出适合目标用途的封面 |
| 活动配图 | 活动主题、使用场景、视觉氛围与需要突出的信息 | 可编辑的活动视觉说明 | 导出适合发布或进一步排版的活动图片 |
| 自由创作 | 一段想法或空白开始 | 可编辑的想法节点或空画布 | 保存一份可继续修改的项目，或导出结果 |

这些是降低起步成本的「创作起点」，不能宣称为已验证效果的模板。未上传产品图时不能承诺还原特定商品；生成模型也不能保证文字、品牌标识和所有细节准确。更适合把重要标题留给后续排版，而非暗示一次生成即可准确交付所有文字。

首版暂不扩大到模板商城、公开社区、多人实时协作、复杂订阅等级和大量视频能力推广。现有工具入口保留，但首屏选择围绕可完成的图片任务。

## 4. 信息架构

### 当前本地版本

```text
创作首页
├─ 继续最近项目（存在项目时）
├─ 从任务开始：商品视觉 / 内容封面 / 活动配图 / 自由创作
├─ 我的项目：搜索、打开、重命名、导入与导出
├─ 我的素材：添加、查找、用于当前创作
└─ 灵感与更多工具
   ├─ 提示词库
   ├─ 生图工作台 / 视频工作台
   └─ 设置、帮助、主题、语言与扩展

项目画布
├─ 顶部：返回项目 / 项目名 / 保存范围 / 导出
├─ 中间：参考素材、创作说明、结果与版本
├─ 上下文操作：根据当前选中内容出现
└─ 生成面板：要求、参考、输出设置、开始生成
```

导航以清晰命名和层级调整为主，无需为了新名称复制页面或改变既有链接。桌面与移动端应使用同一分类。辅助设置收进「更多」后仍需文字标签，不能把所有操作变成不可辨认的图标。

「首页」与「我的项目」职责不同：首页帮助选择下一步，项目页承担全部作品管理。首页仅展示最近项目，不复制完整的管理工具栏。

### 后续平台版本

在上述结构中加入「账号」「积分与账单」「任务记录」，同时把普通用户使用的平台模型配置移到后台。登录应出现在提交云端生成、同步或其他确实需要账号的时刻；公开示例与产品说明不必登录后才能阅读。

平台模式和个人接口模式如需共存，必须清楚显示当前模式、调用方及费用来源。切换模式不可静默改变同一次提交的计费方。

## 5. 首次成功路径

### 当前可实施路径

1. 用户进入首页即可看到「想做什么」以及一个主行动，不先跳出设置弹窗。
2. 选择创作起点并填写想法；空白开始是独立且明确的选择。预设文本可以直接编辑，示例不覆盖用户已经输入的内容。
3. 填写便于辨认的项目名，点击开始后创建真实画布项目，带入所填内容。本轮保留用户输入的项目名，空白画布有独立入口。
4. 在画布中选中并聚焦创作说明或起步节点，提示一个明确的下一步，例如修改要求、添加参考图或生成。不要用需连续确认的长教学遮住工作区。
5. 未配置对应 AI 能力时，在当前任务上下文说明「编辑可继续；生成需要配置图片服务」，给出设置入口，保留项目和输入。配置完成后由用户继续提交，不自动发起付费请求。
6. 生成期间可看到当前状态；错误保留输入、参考和已成功结果，重试有清楚含义。
7. 结果出现后，以「继续修改」「保留此版本」「导出」组织后续行为。成功不以点击生成结束，而以用户获得可使用的作品结束。

### 平台版本路径

保留创作草稿 → 邮箱验证 → 恢复原任务 → 显示服务端报价 → 用户确认提交 → 任务可恢复 → 结果持久保存 → 选择、修改、导出。

邮箱注册与登录建议合并为同一个验证码入口，避免用户判断是否曾经注册。发送失败、验证码错误、过期、返回修改邮箱，都必须保留任务草稿。是否提供体验积分、金额和有效期由经营方案确定；界面不预先承诺未经确认的赠送。

## 6. 渐进呈现与空状态

| 用户所处阶段 | 首先展示 | 需要时再展示 |
| --- | --- | --- |
| 新用户首页 | 创作目标、任务起点、保存范围 | 所有工具、设置、帮助 |
| 回访首页 | 最近项目与继续编辑、新建入口 | 项目管理与历史列表 |
| 空画布 | 添加想法、上传参考、从起点开始 | 节点类型、插件、复杂连线 |
| 编辑想法 | 内容与用途、参考图、输出比例 | 模型、精度、批量数量与高级参数 |
| 等待生成 | 当前任务状态、可继续做的事 | 技术错误明细与请求诊断 |
| 生成成功 | 结果、修改、比较、导出 | 完整提示词、参数与生成元数据 |
| 失败 | 可理解的原因和下一步、输入保留 | 供应商原始错误与支持信息 |
| 无搜索结果 | 当前搜索词、清除筛选 | 新建项目、导入项目 |

不要把「没有项目」「没有搜索结果」「正在读取」「读取失败」合并为同一种空态。读取尚未完成前禁用需要项目数据的操作，避免误导用户创建重复项目。

配置就绪只表示所需字段齐全，不代表网络可达、供应商余额充足或模型权限已验证。界面措辞必须区分「已配置」与「连接已验证」。

## 7. 迭代、比较与项目组织

画布的核心价值是让创作者看见一次次选择，而非展示更多节点类型。

- 默认交互应倾向保留既有作品。再次生成前清晰显示「创建新版本」或「替换当前结果」；是否改变现有默认行为应单独确认，并在迁移中尊重用户配置。
- 每个结果保留来源说明、参考关系和生成条件。选择一个版本后仍能找到上个版本；失败任务不能替换已成功作品。
- 下一阶段提供两张结果并排比较和设为采用版本。比较应展示同等缩放与可放大细节，不需要先做复杂的版本树。
- 项目卡可使用已有图片预览；无图片时显示任务类型和标题。不得为了视觉完整伪造 AI 结果图。
- 节点数量可以出现在详情，但首页优先回答「这是什么项目」「我上次什么时候改过」「如何继续」。
- 导出区区分「作品文件」与「项目备份」：前者便于交付，后者便于恢复编辑。两个动作使用不同名称，不让用户以为导出一张图已备份整个项目。

## 8. 费用与保存信任

### 当前版本必须如实表达

页面可说明「项目保存在当前浏览器，可导出项目备份」。不要将浏览器保存称为云同步；已有可选 WebDAV 配置也不代表所有用户默认拥有平台云存储。清理站点数据、更换设备或浏览器可能影响本地项目可见性。

API Key 由浏览器本地保存，并由前端请求用户配置的接口。生成费用取决于该服务；没有可靠报价时，不显示虚构的积分、人民币金额或「免费生成」。首屏可以提供紧凑的状态提示，详细说明放到设置与帮助。

「已保存」必须源自持久化成功；「保存中」「保存失败」必须有真实状态依据。要实现可靠保存提示，需要先补齐写入完成、异常处理和恢复入口；本次入口重设计不能用装饰性绿勾替代。

### 平台版本计费交互

| 阶段 | 应显示的信息 |
| --- | --- |
| 提交前 | 本次操作、模型或档位、数量、总消耗、可用积分；参数变化后更新报价 |
| 排队与生成 | 已占用积分、当前状态；不可把浏览器关闭等同于成功取消 |
| 成功交付 | 结果与本次结算；只按可交付结果结算 |
| 明确失败 | 原因、可执行下一步、释放或退还状态；区分任务失败与到账完成 |
| 结果待核实 | 任务关联信息与查询入口，不诱导立即再次付费提交 |
| 余额不足 | 现有内容保持不变；充值后回到原任务，重新确认报价 |

钱包主要用于解释和管理消费，不抢占创作主视线。未来充值页展示金额、积分构成、适用范围与规则；不加入没有真实依据的倒计时、虚构热销或默认自动续费。

## 9. 移动端取舍与可访问性

当前目标是让首页、项目管理和起步流程在手机可用，而非宣称复杂无限画布已经完整适配手机。

- 首页主要表单采用单列，页面本身不横向溢出，开始入口无需横向滚动。最近项目可在自己的列表区域横向浏览，并提供「全部项目」入口。辅助菜单保留文字，不依赖鼠标悬停才能发现动作。
- 适合手机的后续任务是上传素材、描述想法、查看进度、选择结果和下载。精细蒙版、复杂连线与大量元素排版优先在桌面完成。
- 对仍需桌面完成的功能，保留草稿并给出明确提示；不得只显示不可操作的缩小版桌面界面。
- 关键按钮使用足够的触控区域；表单具备可见标签，键盘可按合理顺序访问，焦点不会在弹窗关闭后丢失。
- 浅色和深色主题均复用现有 token，状态不只依赖颜色。动画不承担必要信息，并尊重减少动态效果设置。
- 手机软键盘出现后，输入框和提交动作应可滚动到达；返回首页不会丢弃已创建项目。

## 10. 验证指标与研究计划

北极星指标建议为「每周完成并导出至少一份作品的创作者」。本地版本未具备稳定账户标识，最多统计匿名会话或经同意的浏览器标识，不能冒充跨设备独立用户数；账号上线后才使用合适的去重口径。

| 指标 | 明确口径 | 用来判断 |
| --- | --- | --- |
| 首次起步成功率 | 首次首页会话中成功创建且打开项目的会话 / 首次首页会话 | 首页与入口是否易懂 |
| 首次生成成功率 | 至少取得一个可用结果的首次生成任务 / 首次已提交任务 | 配置、模型和错误恢复是否有效 |
| 首次交付耗时 | 从首次进入创作流程到首次作品导出的时间，报告中位数与高分位 | 是否更快拿到可用作品；等待模型与用户编辑分别记录 |
| 起点使用效果 | 按任务入口比较项目创建、生成、导出漏斗 | 起点是否帮助完成任务，而非只有点击量 |
| 继续编辑率 | 在后续会话打开并修改已有项目的创作者 / 有项目的回访创作者 | 项目与版本组织是否带来持续价值 |
| 错误恢复率 | 遇到一次失败后同项目仍完成结果交付的会话 / 失败会话 | 错误文案与重试是否可用 |
| 保存信任问题 | 保存失败、恢复失败、丢失报告及其影响项目数 | 是否损害用户作品与信任 |
| 平台消费质量 | 每个交付结果的真实成本、退款率、付费创作者贡献毛利 | 体验改善是否可持续 |

建议事件包括 `creation_started`、`project_opened`、`generation_submitted`、`generation_succeeded`、`generation_failed`、`artifact_exported`、`project_backup_exported`。错误类别、任务类型和入口可以作为属性；不要默认采集提示词正文、素材内容、邮箱、密钥或带凭据的 URL。技术实现与隐私告知应在启用前评审。

当前没有基线，不承诺「转化提升 30%」之类结果。先做形成性测试，再收集新旧流程的可比数据；量不足时使用任务观察，避免用不稳定的 A/B 数字作结论。

建议邀请覆盖个人创作者、电商素材制作者与小团队成员的少量目标用户，分别完成：第一次做封面、上传商品图修改、返回昨日项目继续、备份并重新打开。观察其独立完成情况，记录卡点与用语；测试后询问「作品保存在哪」「下一次生成是否收费」「如何保留当前版本」，检验心智是否准确。样本选择与结果不能代表整个国内市场。

## 11. 分阶段优先级与验收

### P0：本次入口重设计

已实现、进入验收的范围：任务起步首页、主导航层级、继续最近项目、项目列表搜索排序与预览、批量操作入口、本地保存与配置状态表达。保留真实画布和现有能力，不把后台规划包装成已实现功能。以下是验收标准，不表示每项均已确认通过。

| 场景 | 验收标准 |
| --- | --- |
| 全新浏览器打开首页 | 能看到明确的开始方式；页面不强制配置或展示伪造余额 |
| 选择起点并编辑文字 | 自定义文字进入真实项目；不会被稍后默认值覆盖 |
| 创建起步项目 | 保存真实文本简报、`idle` 图片节点和一条来源连线；点击创建本身不触发 AI 请求 |
| 空白开始 | 能明确选择，创建可编辑空项目，不填充未选择的内容 |
| 重复快速触发开始 | 不应误创建多个同内容项目；错误时保留输入 |
| 未配置 AI | 仍可创建编辑；状态说明正确，入口能到达设置 |
| 已有多个项目 | 最近项目按更新时间展示，继续按钮打开对应项目 |
| 搜索与排序 | 搜索按项目名称匹配；排序与结果一致；无匹配时可清除搜索，不误报没有任何项目 |
| 预览与批量管理 | 图片预览来源于真实项目；选择范围与批量动作一致；删除全部有次级入口与现有确认机制 |
| 本地项目正在读取 | 展示读取状态，不误显示「还没有项目」 |
| 外部灵感源失效 | 首页开始和已有项目仍可使用 |
| 返回与刷新 | 已持久化项目可再次打开；说明保存范围，不承诺未实现的同步 |
| 窄屏与键盘 | 页面本身不横向溢出，主行动可见可达，辅助入口有标签 |
| 双主题与语言 | 对比清晰、焦点可见，新文案遵循既有语言机制 |
| 既有用户回归 | 原路由、项目、导入导出及配置入口继续可达 |

### P1：画布内完成与信任

下一轮优化空画布引导、真正的保存状态、明确的生成配置回路、结果比较，以及作品导出与项目备份区分。以首次可用作品和回访继续编辑验证价值。上述项目不能因为写入本文就标为已实现。

### P2：账号与付费闭环

邮箱身份、服务端报价和任务、积分账本、私有项目存储、异常恢复与最小运营后台具备后，再上线收费入口。详细约束延续 [产品策略](./PRODUCT-STRATEGY.zh-CN.md) 与 [安全及计费方案](./SECURITY-BILLING.zh-CN.md)。任务、账本、保存与交付一致性是开放收费前的验收门槛。

### P3：团队与扩展

先验证异步评审、共享素材与项目交付需求，再决定角色权限、共享钱包、版本评论和实时协作的投入。视频与自动化能力依照使用频率和成本增加曝光，不以菜单数量衡量产品成熟度。

本文未修改实际超时、重试、数量、并发或费用边界。任何对应数值的实施均需按仓库规则另行说明并确认。已检查中英文 TODO，其现有事项为 Agent 适配与 Skill 后续工作，未被本轮完成，无需移除。实际前端变更已同步写入中英文 Pending Tests 和 CHANGELOG 的 Unreleased；后续账号、积分和云保存规划未被列为已实现。
